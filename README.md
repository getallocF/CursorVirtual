# PaperDollTouch — audited experimental source (v0.2.0)

**Status: source prototype only, not a complete inventory mod. No new `.so` or `.levipack` is bundled.**

This project starts from the one attachment that was actually available (`PaperDollTouch.levipack`), audits its native library, and uses the public LeviLauncher Android Preloader API documented for native mods. The two additional ZIPs mentioned in the request were not present in the conversation upload.

## What this source implements

- Correct public native-mod lifecycle registration with `PL_REGISTER_MOD`.
- Typed configuration through `pl::config::ConfigFile`.
- A tested, portable relative-delta cursor engine: pointer starts centered, trackpad hit-test, sensitivity, smoothing, canvas clamping, and drag reset.
- A manual, opt-in Mod Menu cursor-preview module based on public input callbacks and the public HUD image-overlay API.
- A fixed white pointer image registered once; input is consumed only for gestures that begin inside the configured trackpad rectangle. Touches that start outside this rectangle pass through to Minecraft.
- A disabled-by-default safety posture. A zero-sized trackpad and zero-sized canvas disable capture.
- Host unit tests for the cursor math.

## What is deliberately not claimed

The public SDK surface inspected here exposes touch callbacks and generic HUD overlay drawing, but does **not** expose a supported inventory-screen lifecycle callback, inventory-slot geometry/hover selection, or paper-doll model rotation API. I did not find version-verified Minecraft 26.60 signatures or source for those internals in the supplied package. Therefore this source does not install any speculative game hook and does not implement:

- automatic cursor show/hide on inventory open/close;
- accurate green highlight of the real inventory slot under the cursor;
- head/model rotation on the actual Minecraft paper-doll preview;
- automatic input-state cleanup triggered by inventory GUI close (the mod's disable/unload lifecycle is handled).

Those are hard blockers for calling this a completed PaperDollTouch mod. The manual cursor preview must be treated as an experimental SDK integration until input/render coordinate units are calibrated on the target LeviLauncher build. Its module is off by default and its trackpad rectangle is disabled until configured.

## Configure the experimental cursor core

The files under `config/` are packaged with the mod and also generated by `ConfigFile` at first load. Before manually enabling the preview module, set these values in `config/config.json` to match the input and HUD-overlay coordinate space on your device:

- `screenWidthUnits`, `screenHeightUnits`: canvas dimensions in those coordinate units;
- `trackpadX`, `trackpadY`, `trackpadWidth`, `trackpadHeight`: a dedicated area physically separate from all Minecraft buttons and slots;
- `sensitivity`, `smoothing`: motion tuning.

Values default to zero for dimensions and trackpad size so the callback does not consume input by accident. I have not confirmed the coordinate mapping on a running Minecraft 26.60 client, so do not enable the module until those values have been calibrated. This is not a substitute for GUI detection.

```sh
cmake -S . -B build-host -G Ninja -DCMAKE_BUILD_TYPE=Debug
```

Host mode builds only the portable cursor-core test, not the Android mod.

## Android/Termux build (ARM64 Android phone)

The native mod build depends on LeviLauncher Preloader Android SDK 0.2.2 and pinned public C++ dependencies, fetched by CMake. A generic Termux host compiler is **not** an Android NDK and must not be substituted: that can create a library linked to Termux runtime paths.

### 1. Install Termux build tools

Use a current Termux installation, then run:

```sh
pkg update && pkg upgrade
pkg install -y git cmake ninja clang lld make zip unzip p7zip aria2 binutils python
```

### 2. Install an Android ARM64-hosted NDK

The official Google Linux NDK archives target Linux x86-64, not native Termux ARM64. One community-maintained option is the ARM64 Termux NDK at https://github.com/lzhiyong/termux-ndk/releases (the release page lists an r29 AArch64 build). Review and trust the source before installing third-party toolchains; this is not an official Google distribution.

The release project documents these asset names:

```sh
mkdir -p "$HOME/Android" && cd "$HOME/Android"
aria2c -x 8 -s 8 https://github.com/lzhiyong/termux-ndk/releases/download/android-ndk/android-ndk-r29-aarch64.7z
7z x android-ndk-r29-aarch64.7z
rm android-ndk-r29-aarch64.7z
```

Check that the extracted directory contains `build/cmake/android.toolchain.cmake`. If its directory name differs, set `ANDROID_NDK_HOME` to the extracted NDK root. Some scripts inside prebuilt toolchains may need `termux-fix-shebang`; do not modify binary files. Android ARM64-hosted NDK distributions are community-maintained and may need extra adjustments on a particular device.

### 3. Build and verify

Download and extract this source ZIP, then run from its project directory:

```sh
export ANDROID_NDK_HOME="$HOME/Android/android-ndk-r29"
bash scripts/build-termux.sh
```

The script configures CMake for `ANDROID_ABI=arm64-v8a` and `ANDROID_PLATFORM=android-28`, fetches pinned public SDK/dependencies, compiles and links, strips the library, and checks output metadata and SHA-256. Expected outputs, **only if every step succeeds**, are:

```text
build-arm64-v8a/libPaperDollTouch.so
build-arm64-v8a/PaperDollTouch-0.2.0-arm64-v8a.levipack
```

If configuration/build fails, preserve the first CMake/compiler error; do not rename the old `.so` as if it were a fresh build. First-time build needs network access to GitHub. The current build container has no Android NDK/toolchain installed and could not resolve GitHub DNS, so it could not produce or verify an Android binary.

## Install

Only install a newly built `.levipack` if the script creates it and the library checks pass. Import the `.levipack` through LeviLauncher, or use its documented native-mod import flow. This prototype is explicitly marked experimental; the manual cursor preview is not GUI-aware.
